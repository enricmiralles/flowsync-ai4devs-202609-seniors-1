# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**flowsync-ai4devs** is an educational full-stack application built for the AI4DEVS course. It demonstrates authentication, user management, and API design with a modular learning structure organized by course sessions (modules).

- **Course Structure**: Material is organized in sessions (s1, s2, s3, etc.), with each session having a `start` branch for starting work and an `end` branch containing the solution
- **Delivery**: `s(N+1)/start` is the solution for session N, so modules are published strategically to avoid exposing solutions early
- **Target**: Senior developers learning full-stack development practices

## Architecture

### Backend (AdonisJS 7 + TypeScript)

The backend is a RESTful API built with AdonisJS, following a layered architecture:

- **Controllers** (`app/controllers/`): Handle HTTP requests and responses
  - `access_tokens_controller.ts`: Manages login/logout (create/destroy access tokens)
  - `new_account_controller.ts`: Handles user registration (signup)
  - `profile_controller.ts`: User profile endpoints
- **Models** (`app/models/`): Lucid ORM models representing database entities
  - `User`: Main user model with authentication support (password hashing, access tokens)
- **Middleware** (`app/middleware/`): Request/response processing
  - `auth_middleware.ts`: Validates authenticated requests using access tokens
  - `silent_auth_middleware.ts`: Loads user if token is present, but doesn't require it
  - `force_json_response_middleware.ts`: Ensures all responses are JSON
  - `container_bindings_middleware.ts`: Sets up dependency injection container
- **Validators** (`app/validators/`): Vine validation schemas for request data
- **Transformers** (`app/transformers/`): Format model data for API responses
- **Routes** (`start/routes.ts`): API endpoint definitions organized under `/api/v1`
  - `/api/v1/auth/signup` (POST): Register new user
  - `/api/v1/auth/login` (POST): Get access token
  - `/api/v1/account/profile` (GET): Retrieve user profile (requires auth)
  - `/api/v1/account/logout` (POST): Revoke access token (requires auth)
- **Database**: SQLite (better-sqlite3) with Lucid migrations
  - `database/migrations/`: SQL schema changes with timestamps
  - `database/schema.ts`: Auto-generated schema definitions from Lucid models

Authentication uses AdonisJS's built-in auth system with access tokens stored in `access_tokens` table, allowing stateless API authentication.

### Frontend (React 19 + TypeScript + Vite)

A minimal React + Vite setup for building the UI. Currently a starter template with:
- **Vite**: Fast HMR development server and optimized builds
- **TypeScript**: Type safety throughout
- **Oxlint**: Fast linting for code quality

Structure:
- `src/main.tsx`: Entry point, mounts React app
- `src/App.tsx`: Main component (currently a template)
- `src/index.css`, `src/App.css`: Global and component styles

## Database

**SQLite** is the default and currently only active connection (via better-sqlite3):
- Database file: `backend/.tmp/db.sqlite3` (created on first run)
- Migrations auto-run on server start (AdonisJS configures this)
- To reset database: Stop server, delete `.tmp/db.sqlite3`, restart server

**Schema Management**:
- Define columns in Lucid models (`app/models/User.ts`)
- Run `npm run ace migration:create <name>` to scaffold migration
- AdonisJS auto-generates schema from models if enabled in `config/database.ts`
- Tables are created via timestamped migration files in `database/migrations/`

**Current Tables**:
- `users`: id, email, password, full_name, created_at, updated_at
- `access_tokens`: id, tokenable_id (user), token, type, expiresAt, created_at

## Authentication & Authorization

- **Access Tokens**: Stateless token-based auth (similar to API keys)
  - Login creates a token in `access_tokens` table
  - Sent via `Authorization: Bearer <token>` header
  - `auth_middleware` validates presence and ownership
  - `silent_auth_middleware` loads user if token present (doesn't require it)
- **Authorization**: Currently uses middleware checks; RBAC (role-based) policies go in `app/policies/`
- **Password Hashing**: Uses AdonisJS hash service (bcrypt by default)

## Key Patterns

**Imports**: The project uses TypeScript path aliases defined in `package.json` for cleaner imports:
```typescript
import { User } from '#models/user'
import { ProfileController } from '#controllers/profile_controller'
import router from '@adonisjs/core/services/router'
```

**Responses**: Controllers use implicit JSON responses and throw exceptions for errors:
```typescript
// Implicit: return value becomes JSON response
return { user: user.serialize() }

// Errors: throw custom exceptions with status codes
throw new Unauthorized()
```

**Validation**: Validators are defined in `app/validators/` and used in controllers:
```typescript
const data = await request.validateUsing(MyValidator)
```

**Transformers**: Format model output for API responses:
```typescript
const user = await User.find(id)
return { user: new UserTransformer().transform(user) }
```

## Branch Strategy

This repo uses a module-based branch structure for educational delivery:

- **`main`**: Stable, deployable code
- **`s1/start`, `s1/end`, `s2/start`, `s2/end`, ...**: Session branches
  - `sN/start` = starting point for module N (prework, setup)
  - `sN/end` = solution for module N, and prework for N+1
  - **Pattern**: `s(N+1)/start` == `sN/end` (same commit)
  - Used to control when student solutions are revealed

When publishing to cohort repos, branches are carefully released to avoid exposing solutions too early.

## Testing

Uses **Japa** (AdonisJS test framework) with API client:
- Test files in `tests/`
- Run with `npm run test`
- Write tests for controllers, models, and validation

Example:
```typescript
// Use test API client to make requests
const response = await client.post('/api/v1/auth/signup')
  .json({ email, password, fullName })
assert.equal(response.status(), 201)
```

## Development Workflow

1. **Start the dev server**: `npm run dev` in both `backend/` and `frontend/`
2. **Make changes**: Save files and HMR will reload (backend via hot-hook, frontend via Vite)
3. **Test changes**: Visit `http://localhost:3333/api/v1/` or `http://localhost:5173`
4. **Run linting & types**: `npm run lint && npm run typecheck`
5. **Create migrations** if schema changes: `npm run ace migration:create <name>`
6. **Commit to appropriate branch**: Usually `s1/start` or module-specific branch
